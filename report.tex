\section*{Appendix: Bad vs Good Report Examples}

This section illustrates the difference between weak and strong reports.

\subsection*{Example 1: Parsing Logic}

\textbf{Bad:}
\begin{quote}
We parse the input string and extract the values. We split by spaces and hyphens and convert numbers.
\end{quote}

\textbf{Why this is bad:}
\begin{itemize}
\item No mention of registers
\item No explanation of how parsing actually works
\item Could be written without implementing anything
\end{itemize}

\textbf{Good:}
\begin{quote}
We parse the input using a pointer stored in \texttt{rsi}, which traverses the input buffer character by character. 
Digits are accumulated into integers using \texttt{rax = rax * 10 + (char - '0')}. 
Hyphens (`-`) are used as field separators and trigger storing the parsed value into the corresponding array. 
Spaces indicate transition to the next order. 

We ensure correctness by resetting the accumulator register after each field and advancing the pointer carefully to avoid skipping characters.
\end{quote}

\subsection*{Example 2: State Representation}

\textbf{Bad:}
\begin{quote}
We store orders in arrays and update their values during execution.
\end{quote}

\textbf{Why this is bad:}
\begin{itemize}
\item No structure
\item No memory layout
\item No connection to execution
\end{itemize}

\textbf{Good:}
\begin{quote}
Each order is represented using parallel arrays:
\texttt{order\_id[]}, \texttt{arrival[]}, and \texttt{work[]}, where \texttt{work} holds the remaining work of every order at every station. 

The base address of each array is stored in registers (\texttt{rbx}, \texttt{rcx}, etc.). The element for station \texttt{s} and order \texttt{i} is at index \texttt{s*10 + i}, accessed with scaled indexing, so the same code works for all three stations. 

This design simplifies iteration and allows efficient comparisons when a chef selects the next order. 

\end{quote}

\subsection*{Example 3: Chef Choice Logic}

\textbf{Bad:}
\begin{quote}
We implemented QUICK by selecting the order with the least remaining work at each tick.
\end{quote}

\textbf{Why this is bad:}
\begin{itemize}
\item Just restates the algorithm
\item No implementation detail
\end{itemize}

\textbf{Good:}
\begin{quote}
At each tick, for the current station \texttt{s}, we iterate over all orders and compare their remaining work at that station. 
The current minimum is stored in \texttt{r8}, and the index of the selected order is stored in \texttt{r9}. 

For each order:
\begin{itemize}
\item we check if it is waiting in this station's line (its entry time is at most the current tick),
\item we skip orders that have finished this station (remaining work = 0),
\item we update the minimum if less remaining work is found; on a tie we keep the earlier entry time.
\end{itemize}

After selection, the chosen order's remaining work is decremented and its ID is written into the station's timeline buffer. 

\end{quote}

\subsection*{Example 4: Register Usage}

\textbf{Bad:}
\begin{quote}
We used registers to store temporary values.
\end{quote}

\textbf{Why this is bad:}
\begin{itemize}
\item meaningless
\item no mapping
\end{itemize}

\textbf{Good:}
\begin{quote}
We use:
\begin{itemize}
\item \texttt{rsi} as input pointer,
\item \texttt{rdi} as output buffer pointer,
\item \texttt{rcx} as loop counter,
\item \texttt{r8} for current minimum remaining work,
\item \texttt{r9} for selected order index.
\end{itemize}

Registers are reused carefully, and critical values are preserved across loops to prevent corruption.
\end{quote}
